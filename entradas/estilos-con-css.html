Dando estilo a mi web con CSS

Publicado el 09 de noviembre de 2026

Después de aprender a estructurar el contenido con HTML, tocaba el turno de CSS (Cascading Style Sheets o Hojas de Estilo en Cascada), el lenguaje que se encarga del aspecto puramente visual: colores, tipografías, espacios, tamaños y la disposición de los elementos en la pantalla.

La idea clave: separar contenido y presentación

Lo primero que entendí es que HTML y CSS cumplen roles totalmente distintos y por eso conviene mantenerlos separados: el HTML describe qué hay en la página (su contenido y jerarquía), y el CSS describe cómo se ve. Esto se consigue enlazando una hoja de estilos externa desde la etiqueta <head>: 

<link rel="stylesheet" href="../css/estilos.css" />

Y en el archivo CSS definimos las reglas de diseño:

body {
  font-family: system-ui, sans-serif;
  background-color: #f7f7f9;
  color: #1f2937;
}

h1 {
  color: #2563eb;
}

Conceptos que me costó entender al principio

  • El modelo de caja (box model): cada elemento HTML es, en el fondo, una caja rectangular invisible que tiene su contenido, su relleno interior (padding), su borde (border) y su margen exterior (margin). Entender este concepto me ayudó muchísimo a evitar que las cosas se solaparan.
  • Flexbox: antes colocar elementos uno al lado de otro era un dolor de cabeza enorme; con display: flex y propiedades como justify-content o align-items se resuelve en muy pocas líneas de código.
  • Las clases frente a los identificadores: conviene usar clases (.tarjeta) para estilos que se van a reutilizar en varios elementos, y reservar los identificadores (#cabecera) para elementos únicos de la página.

Un ejemplo sencillo

Por ejemplo, para diseñar una tarjeta con sombra y bordes redondeados:

.tarjeta {
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
  padding: 1rem;
  border-radius: 12px;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.08);
}

Con pocas líneas como estas ya se nota una gran diferencia entre una página "en bruto" y una que resulta agradable y cómoda de leer. En la próxima entrada hablaré de JavaScript, la pieza que falta para que la página reaccione a lo que hace la persona que la visita.
